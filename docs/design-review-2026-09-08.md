# 2026-09-08 设计复审与实施修订

> 2026-09-12 用户补充：区分 Plus 完整自动接力与 Pro 项目读取/子代理协作两个模式。原 Plus 完整目标保留，分层不表示削减需求。最新产品边界及直接读写调研见 [模式修订](modes-and-direct-tools-2026-09-12.md)；模式选择器尚未实现。

本次依据当前用户目标与源码重新审查。本文优先于旧方案中的产品优先级、强制员工分工和必须无人值守才能交付的要求；保留原接力状态机的不抢占、真实回执与故障不冒充完成约束。

## 审查结论

1. **产品依赖倒置。** `src/main.ts:buildAppFromRuntime` 与 `src/runtime-config.ts:parseWebgpt` 让生产启动强制依赖 webgpt-drive。即使用户只想让网页 GPT 阅读项目，也需要配置浏览器控制。基础能力应直接通过 MCP 读取可信登记的项目，不消耗本地模型额度，也无需 worker。
2. **缺少直接项目读取工具。** 现有 18 个工具围绕额度、账本、worker 和线程列表；线程列表不能替代源码内容。新增独立只读入口，支持项目列表、目录列表、按行读取和字面量搜索。
3. **自动闭环尚未接通。** `src/mcp/server.ts:resumeCodex` 明确返回 `RESUME_BACKEND_UNAVAILABLE`；`workerControl` 没有调用后端，却构造成功结果，且仅凭 attempt_id 的输入无法定位父任务。修订为明确不可用，不能让调用方误以为已停止 worker。
4. **持久化不等于恢复闭合。** MCP 层的 patches、manifests 与 completedEnvelopes 仍是内存 Map。底层 durable store 不证明上层重启后可以继续 APPLY 或完整恢复。写入模式发布前必须补足跨层恢复与并发证据。
5. **全账户排空过度扩大权限。** 项目理解完全无需中断任何 Codex 任务。后续自动接力只针对用户明确登记并授权交接的任务；账户可见线程列表不能证明全部 active 任务，也不能授权批量 interrupt。
6. **文档状态漂移。** README 仍称 Wave 1、不连接任何服务，而源码已有生产适配器；历史 R4 只验证线程列表，不能升级为读取文件或完整续跑。现有工程桥是第三方 MIT 上游，保留其版权与未提交改动。
7. **周额度未触发接力。** 原 `quota-gate.ts` 仅以 primary ≤5% 判 depleted，secondary ≤5% 只阻止 return，可能仍报告 Codex 可用。修订为已识别且新鲜的任一窗口 ≤5% 都进入 depleted；短窗口单独恢复不足以回接，回接仍要求 primary ≥20%、secondary >5% 与更新样本。旧 `evaluateQuota` 统一委托给同一判定器，移除缺 secondary 仍允许回接的较弱规则。判定器不调用 interrupt，不自动打开开关。

## 分层方案

| 层 | 用户得到什么 | 依赖与完成条件 |
| --- | --- | --- |
| A 项目理解 | 网页 GPT 获取真实目录、源码与行号，帮用户梳理方案 | 独立 STDIO MCP；可信本机项目配置；不依赖 Codex、浏览器驱动或额度检测 |
| B 受控协作 | 审阅差异、有限写入与测试，交接材料可人工使用 | 保留 Bridge；真实校验与授权；补丁恢复、并发和失败验收通过后再启用 |
| C 可选自动接力 | 额度触发、投递完整账本、持续执行、原任务回接 | 周/短窗口均纳入门控；真实浏览器、worker、interrupt/resume 证据；默认关闭 |

A 层的独立入口与旧 relay 入口共用项目源码包，避免为简单只读用户加载整套接力后端。旧入口保持兼容；后续可以复用只读服务接入同一工具注册表。

## A 层边界

- 配置只从本机显式文件加载；网页只能选择 project_id 与相对路径，不能登记任意本机目录。
- 文件扩展名白名单、隐藏文件/凭据文件/生成目录排除、路径分量校验，拒绝 symlink/junction、Windows ADS、设备名、上级路径和绝对路径。
- 文件体积、行长度、搜索文件数/字节数、目录扫描数与返回大小均有上限；所有不完整结果显式标明，不声称已搜索全库。
- 项目内容作为不可信数据，绝不解释为本机命令。只读入口不执行 shell、模型或仓库脚本。
- 它是应用级文件访问边界，不是面对本机恶意并发改目录者的 OS 沙箱。未被文件名规则识别的源码内秘密仍可能被选中读取；用户应只登记允许分享的源码目录。
- 不修改模型、供应商、权限配置或现有 Tunnel。网页连接需要用户账户实际具备 Developer Mode/隧道能力；不能承诺所有 Plus 账户可用。

## 验收顺序

1. 审查基线：现有 unit、mock integration 与构建；失败与环境限制单列。
2. 本地实现：真实临时文件的目录/读取/搜索测试、越界与链接拒绝测试、通过 MCP SDK 子进程验证发现工具和实际读取。
3. 可复现交付：示例配置、启动/诊断、无个人数据的打包清单、更新 README；不包含历史 evidence、个人配置或第三方二进制。
4. 网页验收：在用户选择的账户上连接新只读入口，实际调用源码工具并对照本地文件。未执行前仅称“本地 MCP 已验证”。
5. B/C 层后续：不能用模拟回执冒充原线程回接、网页账户限额或长时无人值守通过。
