# Pro 交付检查表

目标：Chat 聊天端能亲自读取和分析获准的本地项目，直接修改或显式委派本地执行器，执行验证并依据真实结果连续迭代。不路由至 Codex，不依赖额度交接。

本轮由主模型直接实现和验收。演示工作区用于写入和执行测试；现有源项目的未提交修改受保护。

- [x] 修复后的 webgpt-drive 重新核验 5.6 Sol＋即时；项目包装器按真实页面消息核验回复归属。
- [x] 非 Git / dirty 工作区多轮编辑、版本校验、快照验证、失败拦截、回执与恢复；本地真实文件/进程测试通过。
- [x] 本地跨文件修改、测试失败后修正、第二轮修改及外部修改冲突保护验收。
- [x] 本地 Pro→Bridge→DSH 与网页 Chat→Pro→Bridge→DSH 的真实只读验收。
- [x] 配置、诊断、启动及恢复文档与脚本；持久保存已观察到的 DSH 结果。
- [x] 网页读取与原 Git 补丁提交→验证→应用→回读通过，磁盘修改和回执一致。
- [x] 新连续编辑网页 APPLY：重新验证 4 项测试通过，原工具一次复测成功；网页回读和真实磁盘一致，没有变更权限或绕过检查。
- [x] Pro 核心网页执行闭环验收：读取、两轮开发、验证、应用、回读及可选 DSH 派单均有真实证据。通用终端、大型工程适配、开源发行和长期稳定性不在此验收结论内。

交付验收记录由维护者保留在仓库之外，不随本仓库发布。开源发布、Plus 自动额度接力和通用交互终端不属于已完成项目。

连续编辑采用单独的显式本地配置。文件内容使用 SHA256 前置条件；提案不会直接修改原项目。验证在受限大小的源文件快照中运行本机配置的命令，应用前重新校验整个快照。此机制保护通常的并发编辑，但不是操作系统沙箱或对恶意本地进程的文件系统隔离。
